# Remaining risks and acceptance gaps

This audit does not certify production readiness. No production infrastructure, deployment, real customer records or live outbound messaging was changed.

| Priority / status | Evidence | Required follow-up |
| --- | --- | --- |
| Important, confirmed | `GateService.execute` commits release, then `advancePhaseForReleasedGate` invokes a separate command and catches failures. An idempotent replay returns before retrying phase advancement. | Design a transactional or explicitly recoverable phase transition with characterization tests. Existing release/financial rules must remain authoritative. Not changed in this cleanup. |
| Important, conditional deployment exposure | `workflows/lead-engine/workflows/02-job-status.ts` configures an unauthenticated webhook. Airtable dedupe is search-then-create rather than a uniqueness constraint. | Verify actual upstream authentication/rate controls and concurrent dedupe before trusting live events. No external workflow was deployed or exercised. |
| Important, external integration gap | Website IDs/Airtable intake are not the same authority as operational `lead_` records. | Demonstrate real inquiry → operational opportunity linkage, with stable integration mapping and no duplicate communication. Do not rename external IDs or assume automatic synchronization. |
| Important, operational acceptance | Staging checklist leaves backup/restore evidence incomplete; historical Render runbook coexists with Cloudflare staging runbook. | Run an authorized Neon/R2 restoration drill in isolated targets, record retention, ownership and recovery time. Local synthetic database tests are not a production recovery drill. |
| Known security tradeoff | Staff bearer token in localStorage; JavaScript can read it and session survives tab closure. | Keep CSP and sign-out behavior; assess httpOnly-cookie architecture separately. No authentication redesign undertaken. |
| High advisory in offline tooling, retained | `tools/decks` resolves `image-size@1.2.1` through PptxGenJS; GHSA-5p2g-fcmc-qvqq and GHSA-w3rx-r6r6-pgpr concern malformed-image parser loops. | Website launch conditions | Licensed stock imagery, pending canonical/legal/business configuration and tracking decisions remain in existing decision register. Production tests use intercepted reserved-domain webhooks and no real tracking IDs. | Owner sign-off and deployment-specific checklist. Successful local static validation does not validate real lead delivery or analytics. |

## Explicitly deferred

APEX 2.0 visual redesign, rebranding, new product features, a new framework/database/platform, accounting or CRM replacement, whole-router/service rewrites, speculative query optimization, and removal of archives/migrations/engineering evidence. Large API/service modules are still complexity hotspots; tested extraction can accompany future work without changing canonical ownership.

## Verification limitations

The final validation report identifies exact pass/fail/skip counts. Two integration guard tests are intentionally inapplicable when both in-repository engines exist; they are reported as skipped, not passed. Native Windows packaging, real identity-provider configuration, live object-storage permissions, live webhook delivery, load/soak testing and production recovery were not verified. Secret-pattern inspection found no matching private-key/GitHub-token/AWS-access-key literals in tracked text; this was not a full credential audit of Git history or deployed configuration.
